# application/evaluation

評估相關的 Use case：標準答案、檢索、閾值、向量庫、選型與問答流程的驗收。

## 這個資料夾的檔案

| 名稱 | 類型 | 說明 | 產生方式 | 進版控 |
|---|---|---|---|---|
| `README.md` | 檔案 | 本文件：說明這個資料夾的內容 | 手動維護 | 是 |
| `__init__.py` | 檔案 | 套件標記，內容為空 | 手動維護 | 是 |
| `dataset_check.py` | 檔案 | 標準答案的檢查與統計、開發集與測試集切分、第二次標註抽樣、兩次標註的一致度 | 手動維護 | 是 |
| `retrieval_eval.py` | 檔案 | 檢索評估：記憶庫可用 Gold Facts 原文或總結出的記憶（記憶繼承來源事實的最高分）；三種過濾範圍（不過濾、只搜本人、本人加日期／類別）的精確 cosine 排序、逐題指標、彙總與信賴區間、與最佳模型的配對比較 | 手動維護 | 是 |
| `retrieval_profile.py` | 檔案 | 5.1.7 檢索與規模測試：把記憶庫擴充成 N 筆（虛擬使用者、平移日期、向量加微小雜訊）、每題 8 種過濾情境、延遲百分位數與 QPS、對標註與對精確搜尋的 Recall、過濾後剩下的比例 | 手動維護 | 是 |
| `pipeline_profile.py` | 檔案 | 5.1.7 完整流程的彙總：各階段百分位數與佔比、各階段加總和實際總時間的差距（驗收 < 5%）、LLM 的首 token 時間（伺服器端 prompt 處理＋1 個 token）、prompt 處理與生成的 token／秒、總結寫入的重試與 LLM 以外的時間、量測開銷（分段計時、記憶體取樣執行緒） | 手動維護 | 是 |
| `store_check.py` | 檔案 | 5.1.5 驗收：近似向量庫對精確基準的過濾一致性（每題的過濾加 300 組隨機過濾）、跨人檢查、HNSW Recall@10 | 手動維護 | 是 |
| `selection.py` | 檔案 | 選型（計畫 5.1.9）：依 `configs/selection.yaml` 的硬性門檻篩選，各指標 min-max 正規化後加權排名，權重 ±0.05 的敏感度分析 | 手動維護 | 是 |
| `thresholds.py` | 檔案 | 閾值校準與小候選集評估：每題抽 2–10 筆的候選集（正例含 1 筆 2 分記憶，負例全是 0 分），校準無答案誤召回率 ≤ 5% 的最低閾值，回報誤擋率、錯誤通過率與 Top-1 錯誤率 | 手動維護 | 是 |
| `corpus_check.py` | 檔案 | 對話檢查（每筆 Gold Fact 在正確的人、正確的日期出現一次）與記憶語料的驗收數字（成功率、第一次通過率、Gold Fact 覆蓋率與未覆蓋清單） | 手動維護 | 是 |
| `answer_eval.py` | 檔案 | 5.1.6 驗收：每題完整問答後檢查有答案題是否回答、無答案題是否拒答、引用是否都在 Context 與過濾範圍內、事實更新題是否引用新的記憶；不評估回答品質 | 手動維護 | 是 |
