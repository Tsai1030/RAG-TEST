# ADR 0001：對話記憶的 Embedding 模型採用 ruri-v3-130m

| 項目 | 內容 |
|---|---|
| 狀態 | **提議中（Proposed）**，2026-11-08。5.1.5–5.1.7 在實際流程中確認後改為「已採用」 |
| 決策者 | 專案負責人（審閱中） |
| 依據 | [`docs/analysis/selection_report.md`](../analysis/selection_report.md)、run_id `20261108-010358_selection` |

## 背景

陪伴機器人每天把和使用者的對話總結成日文記憶，存進向量庫，之後依使用者的提問找回相關記憶。產品目前用中文模型 bge-base-zh-v1.5 做 Embedding。系統會商用（D3），正式環境是自架伺服器，不使用外部 API（D2）。

本輪用 20 位模擬使用者、390 場對話、Qwen3-4B 總結出的 641 筆記憶，以及 201 題分級標註的問題（開發 81、測試 120），比較 5 個候選與 1 個對照組。閾值與選型規則在測試集評估前凍結。

## 決定

- **採用 `cl-nagoya/ruri-v3-130m`**（Apache-2.0，512 維，revision 固定在 `configs/models.yaml`），query 加「検索クエリ: 」、記憶加「検索文書: 」。
- **備選 `cl-nagoya/ruri-v3-30m`**：部署環境只有 CPU、或延遲要求很嚴時改用。
- 檢索一定先依 `person_id` 過濾；閾值使用 `configs/thresholds.yaml` 的 ruri-v3-130m 值（cosine 0.849）當第一層，第二層由 LLM 判斷記憶是否回答問題。

## 理由

- 測試集上 ruri-v3-310m、ruri-v3-130m、Qwen3-Embedding-0.6B、ruri-v3-30m 的 nDCG@10 都在 0.859–0.872，差距不顯著；依凍結規則，差距不顯著時選較輕量的模型。
- 加權排名第一（0.920）：Recall@5 最高（0.904）、小候選集的正確記憶誤擋率最低（31.7%，開發與測試一致）、記憶體峰值最省（917 MiB）；權重 ±0.05／±0.10、只看準確度、改用名次正規化，第一名都不變。
- 日文表記差異（漢字、平假名、簡稱）的表現接近 ruri-v3-310m，明顯優於 ruri-v3-30m、Qwen3 與 bge。
- 和產品現用的 bge-base-zh-v1.5 比較：nDCG@10 高 0.17（0.864 vs 0.690），Top-1 正確率高 13 個百分點（82% vs 69%）。

## 考慮過的其他選項

| 選項 | 不採用的原因 |
|---|---|
| ruri-v3-310m | 準確度最高但差距不顯著；閾值在測試集不穩定（誤擋率 32% → 44%）；資源約 1.5 倍 |
| Qwen3-Embedding-0.6B | 對總結雜訊敏感、延遲最長、需要長 instruction prefix |
| multilingual-e5-small | 準確度顯著較差 |
| 維持 bge-base-zh-v1.5 | 準確度顯著最差，日文表記與口語換句話說最弱 |
| GLuCoSE-base-ja-v2 | 與 transformers 5 不相容，未進入評估 |

## 影響

- 產品的向量庫要用新模型重建：所有記憶重新向量化（512 維），舊的 bge 向量不能混用。
- 記憶的 Embedding 與問題的 Embedding 都要加上對應的 prefix，並在程式中統一處理（`ModelSpec.encode_text`）。
- 日期與類別過濾的效果取決於總結 LLM 抽 metadata 的準確度；在 5.1.6 決定過濾的用法前，時間類問題的品質有限。
- 閾值只對 ruri-v3-130m 有效；換模型或換總結 LLM 都要重新校準。

## 重新評估的條件

正式環境的總結 LLM 或部署伺服器規格確定時；HNSW 或完整流程的結果和精確搜尋差異超過信賴區間時；取得真實對話資料或日文母語者抽查結果時；有新的日文 Embedding 模型在公開 JMTEB 上明顯超過 ruri-v3-310m 時。細節見選型報告第 6 節。
