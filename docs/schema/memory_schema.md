# 記憶 Schema（schema_version 1）

陪伴機器人每天把和使用者的對話總結成幾筆記憶，每筆一個 JSON，存進向量庫。程式定義在 `src/memrag/domain/schemas/memory.py`。

## 欄位

| 欄位 | 型別 | 由誰填 | 說明 |
|---|---|---|---|
| `category` | enum | LLM | 8 類之一，見下表 |
| `content` | str | LLM | 1–2 句日文記憶，**唯一被向量化的欄位** |
| `event_date` | date 或 null | LLM | 事件發生或預定的日期；喜好、習慣、基本資料通常是 null |
| `people` | list[str] | LLM | 記憶中提到的人，寫法同對話，例如 `孫の結衣`；沒有就是 `[]` |
| `source_turn_ids` | list[int] | LLM | 根據哪幾句對話，至少一個 |
| `person_id` | str | 程式 | 這段對話的使用者；機器人一定知道在跟誰說話，所以不讓 LLM 判斷 |
| `conversation_date` | date | 程式 | 這筆記憶來自哪一天的對話 |
| `source_log_id` | str | 程式 | 來源對話 |
| `memory_id` | str | 程式 | 由使用者、來源對話與內容算出的穩定 ID |
| `event_date_ord` | int 或 null | 程式 | `event_date` 的 `YYYYMMDD` 整數，供向量庫做範圍過濾 |
| `schema_version` | str | 程式 | 目前是 `1` |
| `gold_fact_ids` | list[str] | 評估資料 | 只在評估時使用，不給 LLM 看 |

## category

| 值 | 日文 | 放什麼 | 例 |
|---|---|---|---|
| `event` | 出来事 | 當天或過去發生的事 | 昨日、娘と駅前の喫茶店に行った。 |
| `plan` | 予定 | 未來的安排 | 11月15日に孫の結衣ちゃんが遊びに来る。 |
| `preference` | 好み | 喜歡或討厭的東西 | 甘い物は好きだが、あんこは苦手。 |
| `relationship` | 人間関係 | 家人、朋友、寵物與彼此的關係 | 長男の健一さんは大阪に住んでいる。 |
| `health` | 健康・体調 | 身體狀況、睡眠、服藥、看診 | 最近、右膝が痛くて階段がつらい。 |
| `emotion` | 気持ち | 情緒、擔心或期待的事 | 一人で夕飯を食べるのが寂しいと感じている。 |
| `routine` | 習慣 | 固定的作息與習慣 | 毎朝6時に起きて、ラジオ体操をしている。 |
| `profile` | プロフィール | 住處、職業、出身等基本資料 | 青森県の出身で、若い頃は郵便局で働いていた。 |

一件事符合多類時，選「之後最可能被用來找這筆記憶」的那一類；例如「膝が痛くて散歩をやめた」放 `health`。

## content 的寫法

- **日文、1–2 句、200 字以內**；必須含假名，避免混入中文。
- **自己完結：** 不看對話也看得懂。主語寫使用者的名字（`佐藤さんは…`），不要寫「彼女」「この人」或省略到看不出是誰。
- **一件事一筆：** 不把不相干的兩件事寫進同一筆。
- **具體：** 保留人名、地名、日期、數量；相對時間要換成日期或寫清楚（「来週」→「11月8日」）。
- **不加標題、不加條列符號、不加評論。**
- **只寫對話裡說過的事，** 不推測。

## 評估資料的對應

測試用的 Gold Facts（`data/00_gold/gold_facts.jsonl`）的 `statement` 也照上面的 `content` 寫法，所以同一件事在 Gold Fact 和記憶中的寫法接近，但不要求完全相同。5.1.4 產生記憶後，再把記憶對應到 Gold Fact（`gold_fact_ids`）。
