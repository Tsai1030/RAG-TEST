## 1. 結論

1. 在 LLM 總結的日文對話記憶上，ruri-v3-310m、ruri-v3-130m、Qwen3-Embedding-0.6B、ruri-v3-30m 的檢索準確度相當（測試集 nDCG@10 0.859–0.872，差距不顯著）；multilingual-e5-small 與 bge-base-zh-v1.5 顯著較差。
2. 依凍結的加權規則，**ruri-v3-130m 第一**：Recall@5 最高、小候選集的正確記憶誤擋率最低、記憶體最省，延遲第三快。權重 ±0.05、±0.10、只看準確度、改用名次正規化，第一名都不變。
3. 前四名準確度差距不顯著時，規則要求選較輕量的模型；ruri-v3-130m 比 310m 與 Qwen3 輕，結論一致。
4. 產品現用的 bge-base-zh-v1.5 比 ruri-v3-130m 低 0.17（nDCG@10），表記差異與換句話說的題目落差最大，建議替換。

## 3. 結果

### 3.1 測試集

| 模型 | nDCG@10（記憶庫） | 95% 信賴區間 | Recall@5 | Top-1 正確 | nDCG@10（標準事實） | 無答案誤召回 | 正確記憶誤擋 |
|---|---:|---|---:|---:|---:|---:|---:|
| ruri-v3-310m | 0.872 | 0.829–0.913 | 0.889 | 83.0% | 0.916 | 4.8% | 44.2% |
| ruri-v3-130m | 0.864 | 0.821–0.902 | **0.904** | 82.1% | 0.914 | 6.2% | **31.7%** |
| qwen3-emb-0.6b | 0.863 | 0.820–0.903 | 0.846 | **84.9%** | **0.932** | 4.6% | 32.8% |
| ruri-v3-30m | 0.859 | 0.819–0.896 | 0.899 | 80.2% | 0.917 | 6.9% | 33.1% |
| e5-small | 0.815 | 0.766–0.861 | 0.827 | 77.4% | 0.886 | 6.8% | 50.8% |
| bge-base-zh-v1.5（對照組） | 0.690 | 0.621–0.755 | 0.687 | 68.9% | 0.791 | 6.1% | 53.3% |

- 記憶庫上與最佳（310m）的配對比較：130m −0.009、Qwen3 −0.009、30m −0.013，區間都含 0；e5 −0.057、bge −0.182，顯著較差。
- 130m 與 310m 逐題比較：310m 較好 25 題、較差 24 題（共 106 題），沒有一致的優劣。
- 開發集與測試集排名一致。唯一明顯的變化是 310m 的誤擋率（開發 32% → 測試 44%）：它在測試題上的分數偏低，開發集校準的閾值顯得太高，表示 310m 的閾值較不穩定。

### 3.2 硬性門檻

5 個候選全部通過：都可商用（Apache-2.0 或 MIT）、只搜本人時前 10 名沒有出現別人的記憶、小候選集無答案誤召回的信賴區間下限 2.5%–4.3%（≤ 5%）、Nano 上延遲 p95 ≤ 84 ms（門檻 500 ms）、記憶體峰值 ≤ 1.7 GiB（門檻 3 GiB）。

### 3.3 加權排名

各指標在候選間 min-max 正規化（最好 1、最差 0）後加權：

| 排名 | 模型 | 分數 | nDCG@10（40%） | Recall@5（25%） | 誤擋率（20%） | 延遲（10%） | 記憶體（5%） |

| 1 | ruri-v3-130m | **0.920** | 0.864 | 0.904 | 31.7% | 30.9 ms | 917 MiB |
| 2 | ruri-v3-30m | 0.874 | 0.859 | 0.899 | 33.1% | 17.9 ms | 938 MiB |
| 3 | ruri-v3-310m | 0.751 | 0.872 | 0.889 | 44.2% | 39.9 ms | 1,450 MiB |
| 4 | qwen3-emb-0.6b | 0.608 | 0.863 | 0.846 | 32.8% | 83.6 ms | 1,356 MiB |
| 5 | e5-small | 0.097 | 0.815 | 0.827 | 50.8% | 19.8 ms | 1,688 MiB |

### 3.4 敏感度與穩健性

| 檢查 | 第一名 | 排名 |
|---|---|---|
| 凍結規則 | ruri-v3-130m | 130m 0.920 > 30m 0.874 > 310m 0.751 > Qwen3 0.608 > e5 0.097 |
| 每個權重 ±0.05（規則要求） | ruri-v3-130m | 10 種組合都不變 |
| 每個權重 ±0.10（參考） | ruri-v3-130m | 10 種組合都不變 |
| 只看準確度（延遲、記憶體權重歸零，參考） | ruri-v3-130m | 130m 0.929 > 30m 0.853 > 310m 0.788 > Qwen3 0.690 > e5 0.000 |
| 改用名次正規化（參考） | ruri-v3-130m | 130m 0.850 > 310m 0.613 > 30m 0.525 > Qwen3 0.438 > e5 0.075 |

min-max 正規化會放大小差距（nDCG@10 0.859–0.872 會變成 0.77–1.0），所以第二名之後的順序對方法敏感；第一名在每種方法都相同。「只看準確度」對應部署伺服器資源充足、延遲與記憶體不構成限制的情況（D2）。

## 4. 強弱項與失敗案例

### 4.1 依問題類型（測試集、記憶庫、只搜本人，nDCG@10）

| 模型 | 直接問（24） | 換句話說（24） | 表記差異（23） | 指定人物（21） | 時間／類別（14） |
|---|---:|---:|---:|---:|---:|
| ruri-v3-130m | 0.938 | 0.865 | 0.886 | 0.932 | 0.595 |
| ruri-v3-30m | 0.969 | 0.843 | 0.862 | 0.924 | 0.597 |
| ruri-v3-310m | 0.957 | 0.882 | **0.945** | 0.925 | 0.511 |
| qwen3-emb-0.6b | 0.960 | 0.871 | 0.862 | 0.943 | 0.565 |
| e5-small | 0.940 | 0.760 | 0.785 | 0.930 | 0.573 |
| bge-base-zh-v1.5 | 0.901 | 0.636 | 0.595 | 0.839 | 0.356 |

- **表記差異（漢字、平假名、簡稱）** 是模型之間差距最大的項目。ruri-v3-310m 最強（測試 0.945、開發 0.902），130m 次之；30m 與 Qwen3 在開發集 LLM 記憶庫上只有 0.79 與 0.68，雜訊多時較弱。bge 只有 0.60，常把無關的記憶排第一（例：「にくじゃが、うまくできたんだっけ？」第一名是金沢のおでん的記憶）。
- **時間／類別題** 所有模型都低（0.36–0.60）：「先週なにしたっけ？」這類問題的語意和記憶內容幾乎無關，模型只能抓到含「今日」「昨日」的記憶（例：「翔くんは…クリスマスイブに外食する」）。這類問題要靠日期與類別的 metadata 過濾，不是換 Embedding 能解決的。
- **ruri-v3-130m 的失敗案例**（測試集 nDCG < 0.5 共 9 題）：4 題是上面的「先週」類問題；3 題是表記差異（「ねがえり」「どうぶつえん」用平假名，310m 都答對；「和田さんとどこ行く」被和田さん的人物背景蓋過）；2 題是換句話說（「息子の店を手伝った」被「浩二の店」的背景記憶蓋過）。
- **總結品質造成的錯誤** 對所有模型都一樣：記憶裡留著「今日」「昨日」、內容太模糊（「井上さんは陽葵と関係がある」）、甚至混入中文（「浩二是焼津で魚屋をやっており」）。這些記憶會擠掉正確的記憶，影響比模型之間的差異還大。

### 4.2 小候選集

- 閾值調到不亂送記憶（誤召回 ≈ 5%）時，所有模型都有 3–5 成的正確記憶被擋。同一個使用者的記憶主題常常相近，單靠 cosine 分數分不開。
- 實際流程要有第二層：閾值放寬一些，讓 LLM 判斷記憶有沒有回答問題（計畫 5.1.6 的流程），必要時下一輪評估 Reranker。
- ruri-v3-130m 的誤擋率在開發與測試都最低（29% → 32%），閾值最穩定；310m 從 32% 變成 44%。

## 5. 與公開 JMTEB 分數比較

| 模型 | 公開分數（MTEB 7 個日文文件檢索資料集） | 公開排名 | 本專案 nDCG@10（測試、記憶庫） | 本專案排名 |
|---|---:|---:|---:|---:|
| ruri-v3-310m | 83.98 | 1 | 0.872 | 1 |
| ruri-v3-130m | 83.80 | 2 | 0.864 | 2 |
| ruri-v3-30m | 81.94 | 3 | 0.859 | 4 |
| qwen3-emb-0.6b | 80.30 | 4 | 0.863 | 3 |
| e5-small | 72.71 | 5 | 0.815 | 5 |

- 排名相關係數（Spearman）0.90，公開分數是可靠的篩選依據。
- 差異：公開資料集是長文件檢索，本專案是 1–2 句的短記憶、同一人的相似干擾與口語問題，所以模型之間的差距變小（前四名差距不顯著）。Qwen3 在本專案相對較好，尤其在標準事實記憶庫上（0.932，第一），表示它對整齊的文字很強，但對 LLM 總結的雜訊較敏感（開發集表記差異題 0.85 → 0.68）。
- bge-base-zh-v1.5 是中文模型，沒有日文公開分數；本專案的結果和它的定位一致（日文表記與口語換句話說最弱）。

## 6. 決定

| 角色 | 模型 | 理由 |
|---|---|---|
| **主選** | ruri-v3-130m（`cl-nagoya/ruri-v3-130m`，Apache-2.0，512 維） | 加權第一且在所有穩健性檢查都第一；Recall@5 最高、誤擋率最低且開發與測試一致；表記差異接近 310m；延遲約 310m 的 77%、記憶體峰值約 63% |
| **備選** | ruri-v3-30m（Apache-2.0，256 維） | 只有 CPU 或延遲要求很嚴時使用：Nano CPU 單句 23 ms（130m 是 78 ms），準確度差距不顯著；代價是表記差異與雜訊下較弱 |
| 不選 | ruri-v3-310m | 準確度最高但差距不顯著；誤擋率高且不穩定；資源約 130m 的 1.5 倍 |
| 不選 | Qwen3-Embedding-0.6B | 準確度相當，但對總結雜訊敏感，延遲最長（CUDA 84 ms、CPU 435 ms），需要長 instruction prefix |
| 不選 | multilingual-e5-small、bge-base-zh-v1.5 | 準確度顯著較差 |

### 不適用的情境

- 非日文或跨語言的記憶（本輪只測日文，D6）。
- 長文件、需要超過 512 Token 的內容（本輪的記憶都在 200 字內）。
- 只靠 Embedding 回答時間類問題：「先週」「今月」這類問題一定要搭配日期過濾或時間解析。

### 需要重新評估的條件

- 正式環境的總結 LLM 確定後（目前用 Qwen3-4B），用 `memrag corpus build` 重做記憶庫再評估；總結品質改善時，Qwen3 等對雜訊敏感的模型可能變好。
- 部署伺服器規格確定後（D10），重跑延遲與記憶體；若沒有 GPU，重新比較 130m 與 30m 的 CPU 延遲。
- 5.1.5 的 HNSW 或 5.1.6 的完整流程中，主選模型的表現和精確搜尋差異超過信賴區間時。
- 有真實的使用者對話資料或日文母語者抽查結果時。
- 新的日文 Embedding 模型（例如 ruri 新版）在公開 JMTEB 上明顯超過 ruri-v3-310m 時。

## 7. 限制

- 測試集有答案的題目約 106 題，信賴區間約 ±0.04，分不出前四名。
- 資料全部是模擬的；對話、標準答案與池化判斷都由 Claude 撰寫，不是日文母語者（D7）。池化只看前 5 名，且偏向參與的 6 個模型。
- 延遲與記憶體是 Nano 上的單次量測，Qwen3 在量測時用 bfloat16、評估時用 float32。
- 搜尋是精確搜尋；HNSW、向量庫與完整流程的影響還沒量測。

## 8. 重現方式

在 Nano 上（評估會暫停常駐服務，腳本保證重啟）：

```bash
nohup bash scripts/nano_measure.sh \
  "uv run memrag eval run --models all --split dev --corpus memories" \
  "uv run memrag eval run --models all --split test --corpus memories" > /tmp/rag_eval.log 2>&1 &
```

取回後在 Windows 上（不需要模型）：

```powershell
uv run memrag eval rescore results/runs/<開發集 run>          # 套用池化標註
uv run memrag eval calibrate results/runs/<開發集 run> --write # 已凍結時不要再寫入
uv run memrag eval rescore results/runs/<測試集 run>
uv run memrag eval thresholds results/runs/<測試集 run>
uv run memrag select --retrieval results/runs/<測試集 rescore> --thresholds results/runs/<threshold_eval> --probe results/runs/20261107-183526_load_probe
```

同一份語料、標註與向量會得到相同的數字；`eval rescore` 與 `eval thresholds` 會拒絕語料已經變動的評估。
