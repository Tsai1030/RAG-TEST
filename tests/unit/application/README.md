# tests/unit/application

Application 層的單元測試，用小型手寫資料，不讀真實檔案。

## 這個資料夾的檔案

| 名稱 | 類型 | 說明 | 產生方式 | 進版控 |
|---|---|---|---|---|
| `README.md` | 檔案 | 本文件：說明這個資料夾的內容 | 手動維護 | 是 |
| `test_dataset_check.py` | 檔案 | 標註不可跨人、要通過過濾條件、無答案題不可有標註、取代關係、切分穩定且分層、抽樣涵蓋每種類型、一致度把沒列出的配對當 0 分 | 手動維護 | 是 |
| `test_retrieval_eval.py` | 檔案 | 檢索評估：只搜本人時絕不跨人、日期與類別過濾、提問日之後才提到的事實不可見、排序與彙總、記憶繼承來源事實的分數、相關記憶被過濾掉時算 0 分、與最佳模型的配對比較 | 手動維護 | 是 |
| `test_summarize.py` | 檔案 | 總結流程：第一次就通過、附錯誤訊息重試後通過、超過重試上限、語意檢查與去重、只快取通過驗證的輸出、對應到 Gold Fact、使用者稱呼 | 手動維護 | 是 |
| `test_selection.py` | 檔案 | 選型：硬性門檻（授權、跨人、誤召回、延遲）、min-max 正規化的加權分數、權重敏感度會回報第一名改變 | 手動維護 | 是 |
| `test_thresholds.py` | 檔案 | 小候選集：抽樣固定、不含別人的記憶、不抽 1 分的記憶；閾值校準剛好高於最高的 0 分記憶；誤召回、誤擋、Top-1 錯誤率；依題目分群的 Bootstrap 區間 | 手動維護 | 是 |
| `test_corpus_check.py` | 檔案 | 對話檢查（重複 ID、日期不符、事實出現兩次）與語料驗收數字（成功率、覆蓋率、重試次數） | 手動維護 | 是 |
| `test_retrieval_profile.py` | 檔案 | 5.1.7 規模測試的資料與統計：擴充記憶庫的筆數、使用者、向量雜訊（接近但不等於原向量）、日期跨度與可重現；各過濾情境的日期範圍；百分位數、QPS、對精確搜尋與對標註的 Recall、過濾後剩下的比例 | 手動維護 | 是 |
| `test_pipeline_profile.py` | 檔案 | 5.1.7 完整流程的彙總：讀取 llama-server 回傳的 timings（舊版沒有時記為缺值）、首 token 時間與 token／秒、各階段佔比與加總差距、有無呼叫 LLM 分開統計、總結的重試與 LLM 以外的時間、量測開銷 | 手動維護 | 是 |
| `test_answer.py` | 檔案 | 問答：Context 格式含記錄日、去重、排序與字數預算；引用檢查（拒答不可引用）；有答案、閾值擋下不呼叫 LLM、範圍內沒有記憶、LLM 拒答、輸出格式錯誤、未校準不套用閾值；日期過濾退回對話日期 | 手動維護 | 是 |
| `test_answer_eval.py` | 檔案 | 問答驗收：預期回答或拒答的判定、引用別人的記憶算過濾外、事實更新題、彙總數字 | 手動維護 | 是 |
